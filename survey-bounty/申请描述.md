# MiMo 平台额度申请描述

## 正式版（填写用）

我构建了一个大学生问卷悬赏平台（survey-bounty），用 Next.js + Supabase 全栈开发，已部署上线。平台解决的核心痛点是：大学生做课程调研问卷时找不到足够的人填写，传统做法是在微信群发红包求人填——效率低、赖账无保障、过程不可追踪。平台将整个流程线上化：发布者创建悬赏任务、设置赏金和名额，完成者无需注册即可提交截图，发布者审核后通过微信转账付款，完成者确认收款。内置信用评分系统（确认付款 +5 分，仲裁赖账 -20 分）和完整的支付状态机（pending → verified → paid → confirmed / dispute_pending → disputed）。

项目中 AI 驱动的核心模块是「AI 写问卷」功能，调用大模型 API 实现，包含以下设计：

1. **长链推理 + 行为约束**：System Prompt 不是简单的「帮我写问卷」指令，而是设定了一个「行动锁」机制——在用户确认需求理解之前，AI 被禁止生成任何问卷题目，只能做一件事：追问，帮用户把调研需求想清楚。这要求模型在多轮对话中持续追踪上下文、主动推理用户未明说的信息（比如用户提到「课程」，模型需要自行推断受众是学生），并在每轮回复中附带自己的猜测让用户确认而非从零描述。

2. **四轮对话漏斗**：①合并追问（一次性问 3-4 个关键问题，附带推理猜测降低回答成本）→ ②反向排除 + 边界探测（用「你不想要什么样的问卷」这类反向问题挖掘隐性需求）→ ③显隐分离（把已清晰和仍模糊的信息分类展示，模糊部分自行补猜测）→ ④镜像确认（一句话复述核心需求，用户确认后行动锁解除）。每一轮都需要模型基于前几轮的完整上下文做判断：该追问什么、该跳过什么、该替用户补什么猜测。用户首句信息足够时自动跳过前期轮次，直接进入确认环节。

3. **结构化输出提取**：确认需求后，模型输出包含 7 种题型（单选/多选/量表/矩阵/填空/简答/排序）的结构化 JSON，前端自动解析并渲染为可视化题目编辑器，支持拖拽排序、增删改题和一键导出问卷星格式。

目前该功能日均消耗约 X 万 Token（根据实际填写），申请 MiMo API 额度用于将该模块的模型调用从当前服务迁移至 MiMo，以降低运营成本并测试 MiMo 在中文多轮对话场景下的效果。

## 精简版（如果字数限制较短）

我构建了一个大学生问卷悬赏平台（Next.js + Supabase），核心功能是把「微信群发红包求填问卷」标准化为有信用体系和状态追踪的线上服务。其中 AI 写问卷模块调用大模型 API，通过精心设计的 System Prompt 实现了「行动锁 + 四轮对话漏斗」机制：AI 不会接到指令就立刻生成问卷，而是先通过合并追问、反向排除、显隐分离、镜像确认四轮对话帮用户把调研需求想清楚，每轮都基于完整上下文做长链推理（主动猜测用户未明说的信息、判断该追问还是跳过），用户确认后才生成包含 7 种题型的结构化 JSON，前端自动解析渲染为可编辑的题目列表。申请 MiMo 额度用于迁移该模块的模型调用，降低运营成本。
